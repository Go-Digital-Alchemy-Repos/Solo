PHASE 1 — DATABASE SCHEMA (Drizzle + Postgres)
Update shared/schema.ts (additive) with these tables:

1) conversations
- id (uuid pk)
- type (enum: "direct" | "group")
- createdAt, updatedAt
- lastMessageAt (timestamp nullable)
- lastMessageId (uuid nullable)
- createdByUserId (fk users.id)

2) conversation_participants
- conversationId (fk)
- userId (fk)
- role (enum: "member" | "admin")  (for group only; ok for direct too)
- joinedAt
- leftAt nullable
- isMuted boolean default false
- lastReadMessageId nullable
- lastReadAt nullable
Primary key: (conversationId, userId)
Indexes:
- userId + conversationId
- conversationId + lastReadAt

3) messages
- id (uuid pk)
- conversationId (fk)
- senderId (fk users.id)
- type (enum: "text" | "image" | "audio" | "system")
- text (text nullable)
- mediaUrl (text nullable)
- mediaMeta (jsonb nullable) // width/height/duration/mime
- clientNonce (text nullable) // idempotency key from client
- createdAt
- editedAt nullable
- deletedAt nullable
- deletedForAllAt nullable (optional)
Indexes:
- conversationId + createdAt desc
- senderId
- (conversationId, clientNonce) unique where clientNonce is not null (idempotency)

4) message_receipts (optional but recommended for delivery/read)
- messageId (fk)
- userId (fk)
- deliveredAt nullable
- readAt nullable
Primary key: (messageId, userId)
Indexes:
- userId + readAt
- messageId

5) user_presence (optional; can be ephemeral in Redis later)
- userId (pk fk)
- status (enum: "online" | "offline")
- lastSeenAt
- updatedAt

PHASE 2 — BACKEND API (Express) + SOCKET SERVER
Add a new route module: server/routes/dm.routes.ts mounted under:
- /api/dm/...

Add a new socket module: server/realtime/socket.ts

A) REST endpoints (for initial load, pagination, and reliability)
1) GET /api/dm/conversations
- returns conversations for current user, sorted by lastMessageAt
- includes minimal peer info for direct chats: otherUser { id, username, avatarUrl }
- includes unread counts (derive from lastReadAt/lastReadMessageId)

2) POST /api/dm/conversations/direct
Body: { userId: string }
- create or reuse a direct conversation between current user and userId (unique constraint or lookup)
- returns conversationId

3) GET /api/dm/conversations/:id/messages?cursor=&limit=
- cursor pagination (createdAt/id)
- returns messages newest-first or oldest-first with consistent paging
- includes receipt state for current user if supported

4) POST /api/dm/conversations/:id/messages
Body: { type, text?, mediaUrl?, mediaMeta?, clientNonce }
- persists message
- returns message with server id + createdAt
- emits realtime event to participants via socket

5) POST /api/dm/messages/:id/read
- marks read for current user (update lastRead… + message_receipts)
- emits "read_receipt" to other participants

6) POST /api/dm/messages/:id/delete (delete-for-me)
- marks message hidden for current user (implement via per-user delete table OR store in receipts/details)
- For delete-for-everyone (optional): require sender/admin and set deletedForAllAt, emit event

7) DM attachments upload
- POST /api/dm/uploads (multipart) -> returns mediaUrl + meta
- Use existing storage approach (uploads/) or storage adapter if you created one
- Validate size/mime; images required; audio optional

B) Socket.IO events (instant messaging)
Mount socket server alongside Express:
- Authenticate socket connections using the SAME session system as HTTP.
  - Parse and validate session cookie on socket handshake.
  - Attach userId to socket context.
- Join rooms:
  - room per user: `user:{userId}`
  - room per conversation: `conv:{conversationId}` (join only if participant)

Events to implement:
Client -> Server:
- dm:join_conversation { conversationId }
- dm:leave_conversation { conversationId }
- dm:send_message { conversationId, type, text?, mediaUrl?, mediaMeta?, clientNonce }
- dm:typing { conversationId, isTyping: boolean }
- dm:mark_read { conversationId, messageId }

Server -> Client:
- dm:message_created { conversationId, message }
- dm:message_updated { conversationId, message } (edits/deletes)
- dm:typing { conversationId, userId, isTyping }
- dm:read_receipt { conversationId, userId, messageId, readAt }
- dm:presence { userId, status, lastSeenAt } (optional)
- dm:error { code, message }

Reliability rules:
- On dm:send_message, ALWAYS persist to DB first, then emit.
- Use clientNonce for idempotency so duplicate sends don’t create duplicate messages.
- Acknowledge socket sends with an ACK payload { ok: true, message } or { ok: false, error }.

C) Validation + error shape
- Use your standard validateBody + AppError patterns for all DM endpoints.

D) Security + authorization
- Every DM request checks conversation membership.
- Do not allow user enumeration beyond existing app behavior.
- Rate-limit send_message and uploads.
- Sanitize text content.
